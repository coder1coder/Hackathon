# Руководство по локальному запуску проекта Hackathon

Данная инструкция предназначена для разработчиков, запускающих проект впервые. Проект использует гибридную схему запуска: инфраструктура (база данных, брокер сообщений) поднимается в Docker, а приложения (Backend на .NET 8 и Frontend на Angular) запускаются локально на хост-машине.

---

## 🛠 Предварительные требования

Перед запуском убедитесь, что на вашем компьютере установлены и настроены:
1. **Docker Desktop** (с поддержкой Docker Compose).
2. **.NET 8 SDK** (версия 8.0 или новее).
3. **Node.js** (рекомендуемая стабильная версия для проекта — `v16.15.1`, но не ниже `v16`).
4. **DBeaver** (или любой другой клиент для работы с PostgreSQL — по желанию).

---

## 🚀 Пошаговый запуск проекта

### Шаг 1. Запуск инфраструктуры (Docker)
В Docker-контейнерах запускаются только системные сервисы: база данных PostgreSQL и брокер сообщений RabbitMQ.

1. Откройте терминал в корне проекта.
2. Перейдите в папку с Docker-конфигурацией и поднимите контейнеры:
   ```bash
   cd docker
   docker-compose up -d
   ```
3. Убедитесь в Docker Desktop, что все контейнеры (PostgreSQL на внешнем порту 5433 и RabbitMQ на порту 5672) успешно перешли в статус Running.

P.S. можно без RabbitMQ

### Шаг 2. Настройка HTTPS-сертификатов разработчика (.NET)
Для корректной работы Web API через безопасное соединение необходимо создать локальный доверенный сертификат. Выполните в терминале вашего ПК:
```bash 
dotnet dev-certs https --clean
dotnet dev-certs https --trust
```
При появлении системного окна Windows с запросом об установке и доверии к сертификату, обязательно нажмите «Да» (Yes).

### Шаг 3. Установка инструментов и применение миграций БД
Проект содержит несколько контекстов базы данных (DbContext), поэтому при обновлении необходимо явно указывать целевой контекст.
1. Установите глобальный инструмент Entity Framework Core Tools (если он не был установлен ранее):
    ```bash
    dotnet tool install --global dotnet-ef --version 8.0.0
    ```
    Если инструмент уже установлен, но требует обновления под .NET 8, выполните:
    ```bash
    dotnet tool update --global dotnet-ef --version 8.0.0
    ```
2. Перейдите в папку главного API-проекта: 
    ```bash
   cd .\src\Hackathon.API\
    ```
3. Запустите применение миграций к базе данных, явно указав основной контекст приложения:
   ```bash
   dotnet ef database update --context ApplicationDbContext
    ```
Проверка базы данных (DBeaver): На этом этапе вы можете подключиться к PostgreSQL через DBeaver (Host: 127.0.0.1, Port: 5433). После успешного выполнения команды выше, внутри схемы public в папке Таблицы (Tables) появится вся структура таблиц проекта.

### Шаг 4. Настройка секретов (Конфигурация)
Перед запуском бэкенда убедитесь, что в файле appsettings.Development.json или appsettings.json (в проекте Hackathon.API) корректно настроены параметры отправки почты (EmailSettings):
```text
"EmailSettings": {
    "EmailSender": {
        "Server": "smtp.host.ru",
        "Port": 587,
        "Username": "username@host.ru",
        "Password": "password",
        "EnableSsl": true,
        "Sender": "username@host.ru"
    }
}
```
### Шаг 5. Запуск Бэкенда (Web API)
1. Вернитесь в корень проекта (туда, где лежит файл решения Hackathon.sln).
2. Соберите и запустите C# приложение:
    ```bash
   dotnet build
    dotnet run --project .\src\Hackathon.API\
    ```
3. Приложение успешно запущено, если в консоли появились строки:
    `Now listening on: https://localhost:5001` , `Application started. Press Ctrl+C to shut down.`


   Оставьте это окно терминала открытым, чтобы бэкенд продолжал работу.
   
### Шаг 6. Запуск Фронтенда (UI клиент на Angular)

1. Откройте новое (отдельное) окно терминала
2. Перейдите в папку с фронтендом:
    ```bash
    cd .\Hackathon.UI\
    ```
3. При первом запуске установите глобально Angular CLI и скачайте локальные зависимости проекта:
    ```bash
    npm install -g @angular/cli
    npm install
    ```
4. Запустите локальный сервер разработки Angular: 
    ```bash
    ng serve
    ```

### Проверка работы
После того как Angular завершит компиляцию, откройте браузер и перейдите по адресу: `http://localhost:4200/`

Полноценная локальная среда готова к работе и разработке!

### Частые проблемы и их решение (Troubleshooting)
Ошибка компиляции: `Nullability of type of parameter 'exception' doesn't match overridden member` Причина: При переходе на .NET 8 компилятор строго проверяет null-значения для ссылочных типов.

Решение: В файлах инфраструктуры хабов SignalR (например, `TeamChatHub.cs`, `EventChatHub.cs`) в методе `OnDisconnectedAsync` добавьте знак вопроса к типу аргумента: `Exception? exception`.
